# 部署说明

适用于 Linux 服务器（Ubuntu / Debian 系）的单机部署。小规模使用（单年级、千人以内）1 核 2G 内存即可运行。

---

## 一、环境要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Ubuntu 22.04 / 24.04 或同代 Debian |
| Node.js | ≥ 16，推荐 20 或 22 LTS |
| 内存 | ≥ 1 GB（2 GB 更稳妥） |
| 磁盘 | ≥ 20 GB（附件占主要空间） |
| 网络 | 仅需出站，无需对外开放数据库端口 |

> 若内存为 2 GB 及以下，建议配置 2 GB Swap，避免大导出时被 OOM 杀掉。

---

## 二、部署步骤

### 1. 创建运行用户与目录

不建议用 root 运行服务。

```bash
sudo useradd -r -m -d /opt/zongce -s /usr/sbin/nologin zongce
sudo mkdir -p /opt/zongce
sudo chown -R zongce:zongce /opt/zongce
```

### 2. 上传代码并安装依赖

把代码放到 `/opt/zongce`，然后：

```bash
cd /opt/zongce
sudo -u zongce npm install --omit=dev --no-audit --no-fund
```

`better-sqlite3` 含原生模块，安装时会现场编译，需要 `build-essential` 与 `python3`：

```bash
sudo apt-get install -y build-essential python3
```

### 3. 准备环境变量

**不要把 `.env` 放在代码目录**，避免被误提交。建议放在独立路径：

```bash
sudo mkdir -p /etc/zongce
sudo cp .env.example /etc/zongce/zongce.env
sudo nano /etc/zongce/zongce.env      # 填写 ZONGCE_MASTER_KEY 等
sudo chown root:zongce /etc/zongce/zongce.env
sudo chmod 640 /etc/zongce/zongce.env
```

主密钥生成：

```bash
openssl rand -hex 32
```

### 4. 配置 systemd

新建 `/etc/systemd/system/zongce-app.service`：

```ini
[Unit]
Description=Zongce App
After=network.target

[Service]
Type=simple
User=zongce
Group=zongce
WorkingDirectory=/opt/zongce
EnvironmentFile=/etc/zongce/zongce.env
ExecStart=/usr/bin/node --no-warnings server.js
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

# 安全加固
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full
ReadWritePaths=/opt/zongce

# 大导出与并发下载需要较多文件句柄
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
```

启用并启动：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now zongce-app
sudo systemctl status zongce-app
```

### 5. 验证

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3000/
```

返回 `200` 即启动成功。首次启动会自动建库并写入种子数据。

**此时必须立即登录修改默认密码**（见 [配置说明](配置说明.md)）。

## 三、对外访问

推荐两种方式，二选一。

### 方式 A：反向代理（nginx）

```nginx
server {
    listen 443 ssl http2;
    server_name example.com;

    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

    client_max_body_size 25m;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;
    }
}
```

`client_max_body_size` 需大于单文件上限（默认 20 MB），大导出建议同时放宽 `proxy_read_timeout`。

### 方式 B：Cloudflare Tunnel（无需开放入站端口）

适合内网服务器或无法做端口映射的场景：

```bash
cloudflared tunnel login
cloudflared tunnel create zongce
cloudflared tunnel route dns zongce example.com
```

配置 `~/.cloudflared/config.yml`：

```yaml
tunnel: <TUNNEL_ID>
credentials-file: /root/.cloudflared/<TUNNEL_ID>.json
ingress:
  - hostname: example.com
    service: http://localhost:3000
  - service: http_status:404
```

> **注意**：`service` 里的 `localhost` 指的是**承载隧道的那台机器**。如果同一台机器上还跑着其它服务，务必确认端口不冲突——否则域名会指向另一个应用。

## 四、数据与备份

### 必须备份的两处

| 路径 | 内容 |
|---|---|
| `data/` | 数据库（含 WAL 文件） |
| `uploads/` | 全部附件 |

只备份数据库不备份附件，恢复时会丢失证明材料。

### 一致性备份

运行中直接拷贝 `zongce.db` 可能得到不一致副本（有 WAL）。建议：

```bash
# 方式一：停服务后拷贝
sudo systemctl stop zongce-app
sudo tar czf backup-$(date +%F).tar.gz -C /opt/zongce data uploads
sudo systemctl start zongce-app

# 方式二：用 SQLite 在线备份
sqlite3 /opt/zongce/data/zongce.db "VACUUM INTO '/tmp/zongce-snapshot.db'"
```

建议用 cron 每日执行，并保留最近 7~30 天。

### 恢复

```bash
sudo systemctl stop zongce-app
sudo rm -rf /opt/zongce/data /opt/zongce/uploads
sudo tar xzf backup-YYYY-MM-DD.tar.gz -C /opt/zongce
sudo chown -R zongce:zongce /opt/zongce/data /opt/zongce/uploads
sudo systemctl start zongce-app
```

**主密钥必须与备份数据匹配**，否则加密字段无法解密。

## 五、升级流程

```bash
cd /opt/zongce

# 1. 备份
sudo systemctl stop zongce-app
sudo tar czf /tmp/pre-upgrade-$(date +%F).tar.gz data uploads server.js db.js public

# 2. 替换代码（server.js / db.js / public/）
#    注意 public/js/ 与 public/ 是不同层级，避免文件平铺到错误位置

# 3. 恢复权限（用 sudo 上传会变成 root 属主）
sudo chown -R zongce:zongce /opt/zongce

# 4. 若有新依赖
sudo -u zongce npm install --omit=dev --no-audit --no-fund

# 5. 启动并验证
sudo systemctl start zongce-app
sudo systemctl status zongce-app
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3000/
```

**升级后务必确认**：前端资源版本号（`index.html` 里的 `?v=`）已更新，否则用户浏览器会继续用旧缓存。

## 六、排障

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 启动即退出，日志提示主密钥 | `ZONGCE_MASTER_KEY` 未配置或长度错 | 检查 `EnvironmentFile` 路径与密钥格式 |
| 502 / 502 Bad Gateway | 反代指向的端口与 `PORT` 不一致 | 核对 `ALLOWED_ORIGIN` 与 `proxy_pass` |
| 页面能开但接口全 401 | Cookie 未生效，通常是 HTTPS 下的 `Secure` 属性 | 确认反代传了 `X-Forwarded-Proto` |
| 上传大文件失败 | 反代或框架的体积限制 | 调整 `client_max_body_size` |
| 附件下载 404 | 直接访问了 `/uploads/xxx` | 附件不支持直连，须走下载接口 |
| 导出卡住或进程被杀 | 内存不足 | 配置 Swap；减少单次导出人数 |
| 数据库被锁 | 有其它进程持有写锁 | 确认只有一个服务实例在运行 |

**查日志**

```bash
journalctl -u zongce-app -n 100 --no-pager
journalctl -u zongce-app -f
```

## 七、安全检查清单

上线前逐项确认：

- [ ] 已修改管理员登录密码与二级审核密码
- [ ] `ZONGCE_MASTER_KEY` 为随机生成，未提交到版本库
- [ ] `.env` 位于代码目录之外，权限 `640`
- [ ] 服务以非 root 用户运行
- [ ] `data/` 目录权限 `700`
- [ ] 已配置 HTTPS
- [ ] 已配置数据与附件的定期备份，并验证过恢复流程
- [ ] 数据库端口未对外开放
- [ ] 已确认符合所在单位的数据管理与个人信息保护要求
