# 配置说明

本系统的配置分为三层：**环境变量**（部署相关）、**运行时目录**（数据落盘位置）、**业务配置**（通过管理界面修改，存储于数据库）。

---

## 一、环境变量

全部变量见项目根目录 `.env.example`。复制为 `.env` 后按需填写。

### 1. 服务基础

| 变量 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `PORT` | 否 | `3000` | 监听端口 |
| `HOST` | 否 | `0.0.0.0` | 监听地址。仅本机反代访问时可设为 `127.0.0.1` |
| `NODE_ENV` | 否 | — | 设为 `production` 时启用生产行为 |
| `ALLOWED_ORIGIN` | 建议 | — | 允许的跨域来源。部署到域名后填实际地址，如 `https://example.com` |

### 2. 数据加密主密钥（必需）

| 变量 | 格式 | 说明 |
|---|---|---|
| `ZONGCE_MASTER_KEY` | 32 字节密钥的 hex（64 字符）或 base64 | 用于加密身份证号、手机号等敏感字段 |

**生成方式**

```bash
openssl rand -hex 32
```

**重要**

- 此密钥**一旦丢失，已加密的敏感字段无法恢复**。请与数据库分开保管，不要提交到版本库
- 密钥长度不正确时，进程会在启动阶段直接报错退出。这是刻意的 fail-fast 设计，避免以空密钥运行导致敏感字段被写成空值
- 更换密钥前，必须先用旧密钥解密、再用新密钥重新加密，否则历史数据不可读

### 3. 默认初始密码

| 变量 | 说明 |
|---|---|
| `DEFAULT_ADMIN_PASSWORD` | 管理员账号的初始密码。未设置时使用代码内置默认值 |
| `DEFAULT_SECONDARY_PASSWORD` | 管理员二级审核密码的初始值。二级密码与登录密码分离，用于改判、导出、清除等敏感操作 |

> 这两个变量只影响**新建账号时的初始值**与**首次登录判定**。生产环境请务必设置，并在首次登录后立即修改。

### 4. 告警推送（可选）

| 变量 | 说明 |
|---|---|
| `ZONGCE_ALERT_WEBHOOK` | 企业微信机器人 webhook 地址。留空则不推送 |

用于异常与服务健康状态告警。Webhook 地址本身即凭据，不要提交到版本库。

### 5. 对象存储（可选）

| 变量 | 说明 |
|---|---|
| `R2_ACCOUNT_ID` | Cloudflare 账户 ID |
| `R2_ACCESS_KEY_ID` | R2 访问密钥 ID |
| `R2_SECRET_ACCESS_KEY` | R2 访问密钥 |
| `R2_BUCKET_NAME` | 存储桶名称 |

**启用逻辑**：四项**全部填写**时启用 R2，导出包上传到对象存储并返回预签名下载链接；**任一项留空**则自动回退为本地 zip 模式，导出包存放在 `export-jobs/` 目录。

如果不需要对象存储，全部留空即可，不影响其它功能。

## 二、运行时目录

| 路径 | 用途 | 是否入版本库 |
|---|---|---|
| `data/` | SQLite 数据库文件（`zongce.db` 及 WAL 日志） | 否 |
| `uploads/` | 学生上传的证明材料 | 否 |
| `export-jobs/` | 本地 zip 模式下的导出包 | 否 |

**权限建议**

- 运行用户需对上述三个目录有读写权限
- `data/` 建议设为 `700`，仅运行用户可访问
- 备份时 `data/` 与 `uploads/` 必须一起备份，缺一不可

**数据库说明**

- 采用 WAL 模式，运行期间会存在 `-wal`、`-shm` 文件，属正常现象
- 备份时不要只拷 `zongce.db`，应先停服务或使用 `VACUUM INTO` 生成一致性副本

## 三、业务配置

以下配置存储于数据库，通过**管理员界面**修改，不需要改代码或重启：

| 配置项 | 说明 |
|---|---|
| 复核轮次开关 | 控制第一榜、第二榜、第三榜是否开放 |
| 各轮截止时间 | 到期后提交、退回、撤回等操作会被拒绝；留空表示不限 |
| 已认定项目目录 | 可按条目增删改，部分条目按数量计分 |
| 班级与专业对应关系 | 决定班级排序与统计口径 |
| 班长 / 年级负责人指派 | 控制各班级的审核权限归属 |
| 公告与通知 | 公示信息、操作提醒 |

**计分规则**

- 智育成绩按 `Σ(课程成绩 × 学分) × 0.68 ÷ Σ学分` 计算，整学年合并
- 德育单项设 ±20 的安全边界，避免异常录入导致总分失真
- 智育分值限定在 0 ~ 68 区间
- 规则与具体学校的实施细则绑定，**迁移到其他院校必须重新梳理**

## 四、常见问题

**Q：启动报错"未设置环境变量 ZONGCE_MASTER_KEY，禁止启动"**

没有配置主密钥。执行 `openssl rand -hex 32` 生成后写入 `.env`，或写入 systemd 的 `EnvironmentFile`。

**Q：启动报错"ZONGCE_MASTER_KEY 解码后不是 32 字节"**

密钥长度不对。hex 形式应为 64 个字符，base64 形式解码后应为 32 字节。

**Q：导出一直走本地 zip，没有上传到对象存储**

四项 `R2_*` 变量没有全部填写。这是设计如此——任一项缺失即回退本地模式。

**Q：改了业务配置需要重启吗**

不需要。业务配置存储于数据库，保存后即时生效。

**Q：改了 `.env` 需要重启吗**

需要。环境变量在进程启动时读取。

**Q：数据库可以直接用 SQL 工具改吗**

不建议在服务运行时直接改。数据层在内存中持有单例，外部修改不会被运行中的进程感知，且进程关闭时可能回写覆盖。如需批量修改，先停止服务，用独立脚本修改并保存后再启动。
